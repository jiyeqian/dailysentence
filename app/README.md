# 每日一句 · 海报生成器

把 [欧路词典「英语每日一句」](https://dict.eudic.net/home/dailysentence) 的当日内容，
和你在乐词 App 里的「个人信息卡片」模板合成为一张手机海报
（**恒 1080×1920**、9:16 竖版；手机与桌面同一版面，`?fit=device` 才按设备比例出图）。

- 自动抓取：中英文句子、关键词、音标、释义、出处、配图、真人发音
- 保留你模板里的头像 / 昵称 / 坚持天数 / 学习统计卡片
- 全流程在浏览器 Canvas 完成，**你的模板图不会被上传**
- 移动端优先的界面，可「添加到主屏幕」当作 App 使用

---

## 快速开始

```bash
cd app
node server.js          # 默认 http://localhost:8787
PORT=3000 node server.js  # 自定义端口
```

要求 Node.js ≥ 18（只用到内置模块，无需 `npm install`）。

打开页面后会：

1. 从 `/api/daily` 拿到今日内容；
2. 从 `/api/img` 代理下载当日配图；
3. 在浏览器里合成海报 —— 点「保存到相册」即可。

## 接口

| 路径 | 说明 |
| --- | --- |
| `GET /api/daily` | 返回结构化今日内容（JSON）。`?refresh=1` 跳过缓存；上游缺解析时附带 `missing` / `candidates`（Top 3 候选词）/ `fallback`（词典补全结果）。上游取不到时用存档顶上，并带 `fromArchive` / `archiveOnly` / `archiveDate` / `upstreamError` |
| `GET /api/daily?date=YYYY-MM-DD` | 取某一天的**存档**（往期回看）。没有那天的存档返回 404；问的就是今天则仍走上游实时 |
| `GET /api/archive` | 存档列表：`{ today, writable, days: [{ dateISO, date, dateCN, word, en, missing }] }`（新 → 旧） |
| `GET /api/lookup?word=<word>` | 查词典，返回音标 / 释义 / 双语例句（供「关键词补全」切换候选、改词自动重查时调用） |
| `GET /api/img?u=<url>` | 图片代理，仅放行 `static.esdict.cn` 等白名单域名 |
| `GET /api/health` | 健康检查 |

`/api/daily` 返回示例：

## 存档（每日一句基础数据）

每天第一次打开海报，服务端会把这一天抓到的基础数据落一份盘；之后重复抓取只做增量合并。

**存在哪**：`app/data/daily/YYYY-MM-DD.json`，另有 `app/data/index.json` 作列表索引
（索引不存在或坏掉会直接从 `daily/` 目录重建，不依赖单一副本）。`data/` 已在 `.gitignore` 里。

**存什么**：只存海报要用的基础字段 —— 日期、中英文、出处（作者 / 标题 / 描述）、关键词、
音标、释义、例句、用法、配图地址、原文链接、音频地址，外加 `missing`（当天上游有没有给解析）、
`candidates` / `fallback`（兜底内容）与 `firstSeenAt` / `updatedAt` / `rev`。

**不存你的编辑**：手改的文案、上传的模板图、个人信息卡设置仍是「本次会话有效」，刷新后回到默认。

**合并规则**：同一天会被反复抓（上游偶发漏字段、缺字要靠重试补），按「内容更完整的那份为主、
缺的字段用另一份补」合并，不会被一次残缺的抓取覆盖 —— 完整内容在先、残缺内容在后时，
关键词和释义都保得住；只要有一份拿到了释义，这天就不算「上游没给解析」。
内容完全没变则不写盘（先写 `.tmp` 再改名，避免留下半个文件）。

**两个用途**

1. **往日回看** —— 上游只提供当天，以前的句子过一天就没了。**单击海报上的日期胶囊**
   在今日与昨日存档之间来回切（顶栏已删除，没有别的入口）。往期不重跑词典补全链路。
2. **兜底** —— 上游改版或抽风时按「今天的存档 → 最近一天的存档」顶上，并在返回里如实带上
   `archiveDate`，前端提示「正在看 X 月 X 日的存档」，不假装这是今天那句；两级都没有才报错。

写盘失败（例如只读容器）只记一条日志、功能自动降级，绝不影响出图 —— `/api/archive` 的
`writable` 字段会如实报告存档目录可不可写。

## 海报是怎么合成的

两条版面路线，`?long=1` 切到长版：

| | 标准版（默认） | 长版海报（`?long=1`） |
| --- | --- | --- |
| 画布 | **恒 1080×1920**（设计坐标恒 1080 基准；`?fit=device` 才按设备比例） | 按内容长高（下限 = 画布高 1920） |
| 版面 | 三段式：顶部图片 → 句子 → 信息卡 | 文字块（含大标题 / 分隔线）→ 单词卡 → 信息卡 |
| 文字字号 | **固定设计基准**（3 区 50、4 区 44、5 区 36、2 区日期 28）；仅在整块装不下时等比缩小保底 | 旧基准字号（42 / 29 / 25 起），流式向下排 |
| 左右边距 | 正文与信息卡统一 48px | 文字安全边距 84px |

### 标准版（默认）

从上到下三段，互不重叠。**下面所有尺寸都是「设计坐标」（宽恒 1080 基准）**：
实际位图 = 设计坐标 × `U`，由 `render()` 里一次 `ctx.setTransform` 完成缩放。
默认 `U = 1`（位图就是 1080×1920，所以代码里不需要乘比例）；
只有 `?fit=device` 时才 `U = 位图宽 / 1080`、部件与字号随设备等比放大。

1. **顶部图片区**（固定 648px 高）—— 上游配图与相册图都走同一条规则：
   **宽度铺满 1080、高度按原始比例、超出 648px 的部分 `ctx.clip()` 裁掉**，
   下缘再渐隐进海报底色。竖图只显示最上面一段（1179×2098 → 画成 1080×1922，只留顶部 648），
   宽图下方露出一段底色 —— 图片**永远不会溢出到中部区域**（这是修掉的历史 bug：
   原来漏了 clip，竖图一路画到 y≈1285 把中部糊掉）。标准版不再有「原比例 / 铺满」两种模式。
1b. **卡内图片（信息卡）** —— 从模板图里取「自动识别出的那块矩形」：**等比**缩放、面积相当、
   中心对齐，再裁进固定的 984×496 卡片框；换图后可手动调整（见图 1 的手势表）。
   旧实现是把识别矩形**拉伸**填满卡片，比例不合就会变形，现已改掉。

2. **中部句子区**（648 → 信息卡顶，共 728px）—— 日期胶囊固定在这块顶部靠右；
   英文句 + 中文句 + 出处作为一个整体在余下的活动区里**垂直居中**，
   字号是**固定设计基准**（3 区 50、4 区 44、5 区 36、2 区日期 28，见「字号与交互缩放」）：
   短句不再被放大铺满，只在整块装不下时整块等比缩小保底，`margin-x` 与信息卡统一 48px。
3. **信息卡** —— 距左 / 右 / 底**三边等距 48px**，高 496px 固定。

### 长版海报

沿用原来的流式版面：文字块（关键词大标题 + 分隔线 + 句子 + 出处）→ 毛玻璃单词卡
（`ctx.filter = blur()` 自绘：左侧渐变竖条、等宽音标、词性彩色胶囊、释义；
追加例句引用块）→ 信息卡。本阶段长版保持不动，只有入口改为网址参数。

### 绘制层次（自下而上）

1. **背景图** —— 标准版只占顶部图片区；长版仍是整张画布的背景
2. **压暗层** —— 底部渐变 + 四角暗角 + 极轻的胶片噪点
3. **文字块** —— 日期胶囊、句子、出处（长版另有关键词大标题与装饰分隔线）
4. **单词卡片** —— 仅长版
5. **个人信息卡片** —— 从模板图里自动识别白卡位置（近纯白二值化 + 连通域，
   取不接触画布边缘的最大白块）；标准版只借用识别结果决定「从用户图里抠哪一块」，
   卡片自身位置与尺寸固定

### 字号与交互缩放（2026-09-22 第二次重定）

- **字号是固定设计基准，不再自适应放大**：3/4 区（英文 / 中文）44、5 区（出处）36、
  2 区（日期胶囊）28 —— 用户直接给定值，见 `SZ_*` 常量注释。
  进入应用就是这个字号，短句不再被放大铺满；**只有整块装不下活动区时才整块等比缩小保底**
  （`textFit()` 给出 `base`，同样内容恒等 —— 短句 `base = 1`）
- **每个文字区一份交互变换**：`state.fx[id] = { scale }`（`regionFx()` 取，`defaultFx()` 复位）。
  2/3/4/5 都能上下滑动缩放；**3/4/5 一组联动、2 区独立**（`ZOOM_GROUP` 声明，
  `applyZoom(id, z)` 按组写值）。下限全体 0.6；**上限按区不同**：2 区 **3 倍**、3/4/5 区 **1.6 倍**
  （`ZOOM_MAX_BY` + `zoomMaxOf(id)`，钳制与「已到最大」提示都走它）
- 实际字号 = **设计基准 × `base` × 该区 `fx.scale`**。用户缩放叠在保底之上，所以
  **放大仍可主动溢出活动区**（上下同量溢出、仍然居中；下部被白卡自然遮住，日期胶囊画在最后
  所以不会被盖住）—— 因此**保底测量必须按「各区 fx 全为 1」来量**（`textFitBase()` 传
  `UNIT_FX`），否则用户一放大就被保底吃掉，滑了等于没滑
- 日期胶囊**整体随 2 区缩放等比变大**（宽 / 高 / 字号 / 字距 / 内边距 / 圆角一起长）：
  胶囊变高会把活动区推下去并压矮（`chrome` 里含 `date.h + GAP_DATE_BAND`），
  极端时句子被保底略缩 —— 这是用户拍板的取舍：**胶囊永不压句子**，代价是句子在更矮的
  区域里重新居中（绘制侧本来就是比例式，只需改 `computeLayoutStandard` 里的 `h`）
- 日期胶囊被双击删掉后，它那一行（52 + 28）会还给句子，可用高度更大（保底更不容易触发）
- 将来要给文字区加「交互式移动」：在 `state.fx[id]` 里补 `dx/dy`，只改手势与绘制两处
- 长版仍是流式：各段依次向下排，天生不会互相压盖，按需要长高
- 中文逐字断行、英文按词断行，并避免行首出现 `，。、；：？！）】》」』` 等标点

### 配色主题与摇一摇（2026-09-24）

- **`THEMES` 调色板是配色唯一来源**：`night 墨蓝夜空`（默认，数值就是历史上的原值）/
  `paper 暖纸墨字`（唯一浅色、深墨字）/ `pine 松烟墨绿` / `dusk 紫霞暮色`。
  背景渐变（`bgTop/bgBottom`）、图片渐隐（`fade`）、压暗层（`scrim`，rgb 三元组 +
  绘制侧拼 alpha）、四段文字色（`colTitle/colDate/colEn/colCn/colSource`）、
  强调色（`accentA/B` 单词卡竖条、`waveA/B` 波形）、卡片各色（`card*` / `profileBg`）
  全部由 `PAL()` 取 —— **画布绘制与 `buildAnnots` 标注表都不许再写死颜色**，
  新增主题 = 在 THEMES 加一条（循环顺序 = 书写顺序）。`POS_COLOR` 四主题共用（卡面都近白）。
- **`applyTheme(id)`**：写 `state.theme` → 同步 CSS 变量（`--bg/--bg-2` 页面底色、
  `--wave-c1/c2` 波形强调色，styles.css 侧是 `var()` 缺省值）→ `dataset.theme` → 重绘。
  自证：`inspect().theme = { id, name }`（只增字段）。启动顺序 `initTheme()`：
  `?theme=` 优先（**只当次生效、不写存储**）→ `localStorage['ds:theme']` 读回 → `night`；
  无效参数回落默认。
- **摇一摇**（`bindShake`，主题切换唯一入口）：对 `accelerationIncludingGravity` 做
  低通（α=0.15）估计重力、取**线性加速度**幅值 —— 不能用「含重力幅值的差」：
  摇动是方向翻转（+x 推 / −x 拉），含重力的总幅值对两者几乎一样大，判不出来
  （实现时实测踩过）。幅值 > 12 记越峰，600ms 内两次越峰算一次摇，900ms 冷却；
  **只在空闲态生效**（`state.voice` / `state.edit` / `body.raw` 一律忽略）。
  切换时 toast `配色 · <主题名>` 并写入 localStorage（按设备记忆）。
- **iOS 授权**：未授权时 `devicemotion` 事件一个都收不到，`requestPermission` 又必须由
  用户手势触发 —— 「首次摇→提示」探测不到，所以实现为**第一次 pointerdown 顺带请求**
  （捕获段、只问一次、拒绝静默放弃）。桌面没有加速度计：`?theme=` 就是预览与回归的路径；
  回归用 `new DeviceMotionEvent(...)` 合成**对称振荡**（±25，围绕重力）驱动真监听。

### 换图

- **顶部图片**：单击海报上的图片 → 调起手机相册（未定义双击）
- **信息卡**：单击信息卡 → 调起相册；识别只用来决定从这张图里抠哪一块，
  识别失败回退默认比例 `DEFAULT_RATIOS`
- 相册图与上游配图都按**宽度铺满 + 超出裁切**放进固定的顶部图片区
- 换图、隐藏、手动缩放都不持久化：刷新页面或**下拉更新**都回到初始状态

## 界面（无按钮，2026-09-21 手势化）

**界面上一个按钮都没有。** 顶栏已整体删除（`#topbar` 与四个按钮在 HTML / CSS / JS 三层都不存在），
整页只有海报；`index.html` 里只剩两个隐藏的 `file input`（选图的实现载体）。
功能全部由手势承载，唯一提示是首次进入时那行 3 秒后自动消失、操作即收起的 `#hint`：

| 手势 | 作用 |
| --- | --- |
| 长按任意位置 | 保存（iOS 弹浮层出原图，长按图片 → 存储到照片；桌面 / Android 直接下载） |
| 单击顶部图片 / 信息卡 | 调起手机相册选图 |
| 单击英文句（3 区） | **朗读**并升起波形层（等 300ms 确认不是双击）；**只有它会发音** |
| 单击中文句 / 出处 | **不发音**（保留 300ms 判定只为双击删除） |
| 单击日期胶囊 | **今日 ⇄ 昨日存档切换**（等 300ms 确认不是双击） |
| 双击日期胶囊 / 英文 / 中文 / 出处 | 从海报上删掉这个元素，其余内容重新居中（**不再自动放大补位**；**不可逆**，刷新恢复） |
| 在英文 / 中文 / 出处上上下拖动 | **实时缩放中部字号**：上滑放大、下滑缩小（0.6–1.6 倍，叠在保底值上），松手保留 |
| 在日期胶囊上上下拖动 | 只缩放日期：**0.6–3 倍**（2 区上限比句子区高），胶囊整体（含高度）跟着变大 |
| 非句子区（图片 / 卡片 / 空白）向下拉 ≥ 90px | **回到初始状态**（等同重启 App），过阈值时提示「松手即更新」 |
| 摇一摇手机 | 四套配色循环切换（night→paper→pine→dusk），toast 报主题名、按设备记忆；**只在空闲态生效**（播放 / 调整 / 导出页忽略）；iOS 第一次点海报时请求动作权限 |

**换完图会自动进入「手动调整模式」**（换顶部图片或信息卡之后立刻进）。此时上面那一整套手势
**全部让路**（不保存、不更新、不朗读、不删除，也不会再弹相册），只认这两下：

| 调整模式的手势 | 作用 |
| --- | --- |
| 单指拖动 | 在展示窗口里挪图，把想要的区域露出来 |
| 双指捏合 | 缩放（1–4 倍，两指中点位移同时当平移） |
| 单击图片 / 信息卡 | **换一张**（与正常模式同一语义：一下就开相册，不必先「完成」；选完按新目标重新进调整模式） |
| 点被调区域以外的地方 | **完成**（退出调整模式，界面照旧没有按钮） |

进入时**默认什么都不动** —— 就是刚换上的那个比例与位置（`fits = {scale:1, ox:0, oy:0}`）；
底部那行提示常驻到退出为止；退出后调整结果保留，但刷新页面或下拉更新会把它复位。

**这是一套「独立不透明弹层」式的界面**（2026-09-22 第二次重做）：

- 换完图弹出 `#editLayer`：铺满整屏、底色不透明 —— **原海报完全不动、也不出现在层里**，
  层里只有居中的换图区与这张图。上一版「给 `#poster` 加 `translateY` 让该区居中」的做法
  已删除（它把海报其它内容留在视野里、版面杂乱，而且必然有一头移出屏幕），海报的绘制
  从此与 `state.edit` 完全无关（那两处「调整时不裁切」的分支也删了），`bgDraw` 口径不变
- **窗口尺寸 = 该区设计尺寸 × 海报显示比例 `s`**（不放大、所见即所得）：
  1 区约 402×241pt，6 区约 366×185pt。这一条同时保住了 `pxToCanvas()` 的手势灵敏度
  （= `CW / posterRect.width`），所以 fit 数学与 `commitFit()` 一行都没改
- **窗口是圆角矩形**（圆角 = 18 设计值 × s，与信息卡一致）：1 区在弹层里的预览窗口也是圆角，
  但**成品海报里 1 区仍是方角矩形**
- **窗口内清晰、窗口外是同一张图压暗 62% 的其余部分**（`rgba(6, 10, 18, 0.62)`，拖动 / 缩放的
  引导）：整幅图**不裁切**地画在 `#editCvs` 上，再用「整层矩形 + 窗口圆角矩形」的
  `fill('evenodd')` 一次压暗
- **没有任何描边 / 虚线**：亮暗交界就是这块区域的边界（历史上的青色虚线框 `drawEditFrame()`
  已删除，回归有一条源码级断言盯着它不许回来）
- 预览画在**弹层自己的 canvas**（按 `层尺寸 × dpr` 定缓冲、`setTransform(dpr,…)` 后用 CSS px
  坐标绘制），只在 `render()` 末尾的 `drawEditPreview()` 里画一处；视口变化靠
  `watchViewport()` 的防抖重排（海报画布尺寸不变也要重排一次）。弹层 `pointer-events: none`
  （不抢事件，拖动 / 双指 / 点击照旧落到海报上由手势层处理）、`z-index: 25`（低于 `#hint` 的 30）
- **命中判定按窗口 rect 比坐标**（不再用 `hitTestAt`，因为海报被不透明层盖住了）：
  窗口内 = 换同一张，窗口外 = 完成
- 代价：层里看不到海报，所以**「点另一块换图」这条路径不存在了**（用户已确认接受）——
  要换另一块先点窗外完成，再点海报上那一块

**语音播放期是「独占态」**（`state.voice`，2026-09-22）。**只有单击英文句（3 区）才发音** ——
中文句与出处的单击不再朗读，它们的 300ms 判定只为保住双击删除：

| 播放期的手势 | 作用 |
| --- | --- |
| 点波形层（含其中的空隙） | **停止播放**：波形淡出、独占解除、其余区域立刻恢复可操作 |
| 其它任何位置（点 / 长按 / 拖动 / 双击） | 一律无反应 —— 独占态下不保存、不更新、不缩放、不删除、不弹相册 |

- 波形层是**只有竖条的 DOM 浮层**（2026-09-22 去掉原来的 34% 深色底：无背景、无描边、无圆角），
  宽度恒为**正文列宽 × 90%**（`WAVE_W_RATIO`），居中基准是 **3 区文字框**（不是整列）——
  正文左对齐、右侧参差，按整列居中会「左边空得多」（用户指出，实测 49 对 24）；
  偏移夹在列中心 ±10% 列宽内（`WAVE_ALIGN_LIMIT`），正常句子左右留白相等（实测各 23px）；
  位置与宽度由 JS 按 3 区框 / 列宽换算成屏幕坐标写入。**绝不画进 canvas**，所以长按另存的
  1080×1920 与 `?raw=1` 的导出都不受影响（`body.raw` 的屏蔽清单里有它）。
  **面板里没有任何文字 / 图标：波形本身就是停止按钮。**
- 外观三条硬约束：**只有竖条**（`backdrop-filter` 一律不用 —— 一模糊就把底下的英文句糊掉），
  竖条自带极淡 `drop-shadow` 保证亮背景也看得见；**不可太突兀** → 竖条细（9 设计值）、间距大（36）、
  振幅压 45%–85%、整组只占 58% 高度，横向覆盖率约 20%
- 竖向只盖 3 区，外扩**自适应**（`voiceBox()` 上下最多各吃邻居空间的 40%），永远不会顶到中文句
  或日期胶囊；窗口旋转 / 视口变化后跟着重新贴合
- **波形只听音频事件，不听 `play()` 的 Promise**（2026-09-22 修）：`playing` 才升起、
  `pause` / `ended` / `error` / `emptied` 立刻收起，Promise 只用来报错。
  原因是 iOS 下那个 Promise 有迟迟不 settle 的情形（有声音没波形），也可能先 resolve 而真出声
  被吞掉（有波形没声音）
- **进度看门狗**：`state.voice` 期间 500ms 一跳，音频 `paused` 或 `currentTime` 1.5s 不前进
  就收尾 —— 音频被暂停 / 卡死时不一定派发 `ended`，没有它就是「播一会儿停了、波形还挂着」
- **`primeAudio()` 的复位让位给正式播放**：元素带 `__dsTaken` 标记，被 `speak()` 接管后不再插手
- **冷启动首点必须一次成功**（2026-09-22 修「第一次点总失败、等一会儿再点就行」）：
  - 根因：`primeAudio()` 那次 `play()` 要等网络把 mp3 抓够才 settle，300ms 后 `speak()` 又对它
    `pause()` → 浏览器按规范以 `AbortError: The play() request was interrupted by a call to
    pause()` 打断 → `play-rejected`；等一会儿再点就好是因为 mp3 已进 HTTP 缓存
  - 修法四条：`loadDaily` 里 `preloadAudio()` 预热（`Audio` + `preload='auto'` + `load()`，
    **不用 fetch** —— 跨域音频会被 CORS 拦）；`speak()` 复用元素时按
    `a.__dsPlayPending || a.paused === false` 判断「还在挂起 / 已在播」，挂着就**只 seek**
    （`currentTime = 0`），确实停了才 `pause()` + 重播（音量复位两条路都要做）；
    `primeAudio()` 里额外播一段运行时生成的 0.1s 静音 WAV 保底解锁；失败自动重试一次
    （`VOICE_RETRY_MS` 400ms），`play()` 迟迟不 settle 时 `VOICE_KICK_MS` 1500ms 再踢一下
- **没有音频文件绝不出波形**：无 URL 时连解锁都不做，`speak()` 早退并给一句轻提示；
  波形只在 `playing` 升起，所以「没声音却有波形」结构上不可能
- 停止的唯一出口是 `stopVoice(reason)`：点波形 / `pause` / `ended` / `error` / `emptied` /
  看门狗 / 硬上限（`min(20s, 时长 + 1500ms)`）/ `resetToInitial()`。**播完自动收起**；
  每次收尾都落进 `state.voiceDiag`（`inspect().voiceDiag` 可读：原因 + 实际响了多久）
- 播放中的音频元素存在模块级 `activeAudio`（旧实现不留引用，所以根本停不下来）；
  回归用可控的 `Audio` 桩驱动（会走时间、异步派发 `playing`，可切「静默失败」模式），
  既确定又能断言「停止时真的调了 `pause()`」「没真出声就不出波形」

**海报在屏幕上怎么摆**（`#poster` 的 `max-width/max-height` 等比 contain）：

- 宽度充满优先：9:16 的海报左右贴边、竖直居中，上下余量露出 body 底色当色块；
  窗口比 9:16 更扁时按高度适配
- **四角圆角 32 设计值，画进 canvas**（`POSTER_RADIUS` + `render()` 开头的 `roundRectPath` + `clip`）：
  四角因此透明，长按另存的 PNG 本身就是一张圆角卡片；屏幕侧 `syncPosterRadius()` 把
  `#poster` 的 `border-radius` 写成「32 × 显示比例」，与成品对齐。
  ⚠ 口径是「**圆角只许画进 canvas，不许只加 CSS**」——旧条款「不加圆角」是「圆角只在 CSS」时代的
  结论（那时会裁掉四角、显示就不是成品）；现在显示与成品依然一致。CSS 半径也不能写百分比
  （按宽 / 高分别解析，9:16 会变成椭圆角）
- **竖直方向的「居中」指对物理屏居中**（`syncStageCenter()`）：加到主屏的独立应用形态下，
  系统给的布局框比物理屏**矮一个状态栏、且锚在屏幕顶端**（内容仍从 y=0 开始画，状态栏压在上面），
  在它里面居中会让整张海报偏上半个状态栏。真机量到的是上留白 53pt / 下留白 112pt，
  而 iPhone 自己显示同一张 1080×1920 是 83pt / 80pt —— 照片因此压在刘海下、底部多一截黑。
  修法：独立形态下把「物理屏高 − 舞台实际框高」写进 CSS 变量 `--stage-pt`，当作 `#stage`
  的上内边距，把框补回物理屏大小（`pt = S − F` 是精确解，与海报高无关）
- **浏览器里不做这个补正**（`--stage-pt` 恒 0）：那里的布局视口就是可见区，而 `screen.height`
  远大于可见区（还要减工具栏），无条件加偏移会把海报顶出屏幕下沿
- 自适应画布（`?fit=device`）里 `body.adaptive #stage { padding: 0 }` 权重更高、会盖掉补正 ——
  那是对的：那模式下画布比例就等于框的比例，没有可补的偏差
- 自查：`inspect().stage = { standalone, padTop, screenH, frameH }`；真机整屏截图可用像素量测
  复核，判据是**上留白与下留白之差 ≤ 10 设备像素**

- **同一元素既有单击又有双击**（句子三个 + 日期）：走**单槽 `pendingTap` + 300ms 确认** ——
  300ms 内同区域第二击判为双击（删除），否则到期执行单击动作（朗读 / 切换）。
  槽只有一个，快速点不同元素时前一击作废，不会连播多次。
- **列表类元素（图片、信息卡）不定义双击**：双击会让相册连开两次，所以单击立即响应、零延迟
  （内部仍有一道 400ms 防抖兜底）
- **保存按平台分流**（`savePoster()`）：iOS 上 `<a download>` 只会把 PNG 落进「文件」里弹
  Quick Look 预览、存不进相册，而 `navigator.share({files})` 在长按的定时器里已脱离手势调用栈
  会被拒 —— 所以 iOS 弹 `#saveSheet`（一张 blob 原图，长按 → 「存储到照片」，其他平台走
  分享或直接下载）。浮层里的图**不拦 touch 事件**，并覆盖掉了 `#stage` 的 `touch-callout: none`，
  否则 iOS 的长按菜单出不来。文件名统一 `dailysentence-YYYY-MM-DD.png`。
- **下拉与缩放按起点元素分流**：句子上是缩放，其余地方是下拉更新 —— 不靠距离阈值区分，更好预测。
  位移 > 8px 就取消长按与点击判定；`#stage` 加了 `touch-action: none` 压住浏览器滚动与橡皮筋
- **iOS 音频解锁**：单击朗读会先在 `pointerup` 的手势调用栈里用 `primeAudio()` 静音播一下解锁，
  300ms 后确认是单击再正式播 —— 否则 iOS 会拒绝延迟播放
- 已禁用文本选择与系统图片菜单；`index.html` 的 viewport 带 `user-scalable=no`，
  双击不会触发系统缩放
- **回到初始状态只有一条路径**：`resetToInitial(refetch)`，下拉更新与 boot 共用
  （清隐藏、缩放归位、配图与信息卡模板复原、重新抓上游）
- **刷新即初始**：隐藏的元素、换的图片、手动缩放都不记忆（不写 localStorage，也不进服务端存档）
- **昨日切换依赖服务端存档**：昨天没抓过就 `loadDaily` 报错并保持当前内容，前端再补一句
  「还没有 X 月 X 日的存档」，绝不显示错的内容
- `?raw=1` 仍是纯海报输出，不受影响

## 上游格式兼容

欧路词典的页面结构会不定期变动。解析器对已知的几种变化都做了兼容：

| 上游变化 | 应对 |
| --- | --- |
| 音标从「单个 `/…/`」变成「英 `/…/` 美 `/…/`」 | `parseWordLine()` 按 `(英式｜美式｜英｜美)? /音标/` 逐段捕获，把单词与音标彻底分离；渲染时只有一个音标不显示语言标签（与旧版一致），英＋美并存才加标签区分 |
| 分组小标题从「例句：」变成裸词「例句」「常用搭配」 | `isSectionHeader()` 三重判据：页面 `detail_header` 标注 → 冒号结尾 → 已知标题词（`HEADER_WORDS`）或「短小纯中文 + 前面有空行分隔」 |
| 关键词从单词变成**短语**，且词与释义挤在同一行、没有音标、行首还带序号（`1. get something done 使某事被完成，让别人为自己做某事`，2026-09-20） | `parseWordLine()` 先 `stripEnum()` 掉序号；没有音标时以「第一个汉字 / 全角标点」为界切开，前半当关键词、后半作为 `rest` 返回给调用方当第一条释义 —— 于是 `missing` 正确判为 false，不会再误触整条词典补全链路 |
| 用法被拆成 `① …`、`② …` 编号条目，且第二条排在「例句：」**之后**（2026-09-20） | `isUsageBullet()` 按「行首编号 + 够长或有句读」认出用法条目，统一并回同一个「用法详解」段（`usageSec`），不再被 `例句：` 切成孤立一行、也不会被当成中译配错的例句；短编号条目（`1. 下定决心`）仍判为释义，避免误吞释义造成 `missing` |
| 新增「常用搭配」分组 | 归入 `usages` + `usagesTitle` 一并返回，但**海报不渲染**——只当它和例句混在一起时能被正确切开，避免污染释义 |
| 例句的 class 在 `exp` / `eg` 之间摇摆 | 解析只按 `<br>` 切分取文本，不依赖 class |
| 上游整段漏发「解析」内容（页面只剩关键词占位 CSS） | 服务端标记 `missing` 并给出 Top 3 候选关键词；前端展示「关键词补全」区块，选中后查 `/api/lookup` 回填；卡片右下角以 `补` / `选` 圆标注明内容来源 |
| 音标写法不统一：`/dɪˈsiːv/`、`[dɪˈsiːv]`、`/ dɪˈsiːv /` | 渲染前先 `normPh()` 剥掉外层斜杠 / 方括号 / 首尾空白，再统一包一层，避免出现「英 / /dɪˈsiːv/ /」式双份斜杠 |
| 「本句出自」整块缺席，出处变成译文末尾的「——作者」（2026-09-19） | 解析块的「本句出自」仍优先；仅当 source 为空时，才从中文译文末尾摘 `——人名`（只认 ≤25 字、不含句读的名字，解释性破折号如「成功不是终点——失败也非末日。」不会被误摘），摘出后从译文里剥掉 |
| 页脚多出一行法文 `<p class="Hoffmanm author_en">`（录音者署名，不是句子出处） | 不参与 `source` 解析，直接忽略 |
| 词条页把汉字随机换成小图（`dictimgtoword`） | 多次抓取 + 逐位合并补字；按字固定替换补不回的，含缺字的义项 / 例句整条剔除，绝不印残词 |
| 高频访问词条页会被 302 到登录页 | 词条请求不跟随跳转、串行节流 + 长连接复用，302 计为失败重试 |

去标签时区分内联 / 块级：`<span class="key">` 这类高亮标签直接删掉**不补空格**，
只有 `</p>`/`<br>` 等换行标签才换成一个空格 —— 否则中文例句会印出
「我对他所说的感到 失望 。」这种多余空白。

音标过长时（如 `extraordinarily` 配双音标），单词卡片的音标字号会从 31px 逐档缩到最低约
18.6px，保证不溢出卡片宽度。关键词同理：短语（`get something done`）会让 47px 的词号
逐档缩到最低约 27px；海报顶部大标题本身已有 118px → 56px 的自适应缩小。

**改解析前后都跑一遍**：

```bash
node app/parse-check.js     # 上游各种历史结构 + 今日结构的解析断言
```

> 若上游又推出**词表之外的新裸标题**，那一行会被并进上一段。此时把它加进 `server.js` 的
> `HEADER_WORDS` 即可。

## 调试参数

- `?raw=1` —— 只显示海报本身，便于导出/截图
- `?theme=night|paper|pine|dusk` —— 预览指定配色（**只当次生效、不写记忆**；桌面没有加速度计，
  这是预览/回归四主题的路径，见「配色主题与摇一摇」）
- `?bg=natural|cover` —— 指定背景模式（**只对长版有效**；标准版固定「宽度铺满 + 超出裁切」）
- `?long=1` —— 长版海报（旧参数 `?ex=1` 同样生效）
- `?word=&en=&cn=&source=` —— 覆盖文案（方便排版测试）
- `?ph=ˈɪmpʌls`｜`?ph=英:ɪɡˈzæmpl|美:ɪɡˈzɑːmpl` —— 覆盖音标（方便测试单/双音标排版）
- `?debug=1` —— 把命中表与坐标换算挂到 `window.__ds`，供交互回归脚本按区域 id 反查屏幕坐标点击
- `?diag=1` —— **真机诊断页**（2026-09-22 加）：页面顶部叠一段纯文本关键数字（`#diag`），
  内容取自模块状态（不依赖 `debug=1`）：形态（standalone / display-mode）、屏幕与安全区、
  舞台补正（`STAGE_INFO`）、海报显示尺寸与 CSS 圆角、版面（base / 活动区 / 卡片 / 顶图）、
  四个文字区字号与 `fx`、`hasAudio` 与 `voiceDiag` 全字段、`state` 摘要、UA。
  该模式下**放开文本选择**并**让「长按保存」让路**，所以手机长按面板就是系统的「全选 / 拷贝」——
  报 iOS 专属问题（音频会话 / 主屏形态安全区 / 真机字形）不用截图。铁律不变：纯文本、零按钮、
  不常驻（不带参数时 `#diag` 始终 hidden）、绝不画进 canvas（`body.raw` 隐藏清单里有它）
- `?fit=device` —— **画布自适应开关（默认关）**：开启后按设备分辨率出图（位图 = 屏幕比例、宽度不低于 1080）。
  默认关闭是因为真机实测「满屏自适应不够美观」（版面随屏幕差异大、iOS 启动瞬间视口高度会变导致跳一下）；
  框架完整保留，将来想在个别设备启用只需带这个参数

环境变量：

- `PORT`（默认 8787）、`HOST`（默认 0.0.0.0）
- `DS_DATA_DIR` —— 存档目录，默认 `app/data`（测试用它把存档写到临时目录，不污染真实存档）
- `DS_DAILY_PAGE` —— 覆盖上游页面地址，用来验证「上游挂了」时的存档兜底

## 版面标注通道（人机沟通用，2026-09-21 起）

改版式时不靠「截图 + 手绘标注 + 对方识图」，用**编号**说话：编号标注图给人看、
坐标清单（JSON）给 AI 读，两边共用同一套编号。前提：服务在跑（`node server.js`）。

```bash
# playwright 是外挂工具，不在 package.json 里，借 WorkBuddy 的 node_modules 跑
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  node app/inspect.js --tag before --raw \
  --word impulse --en "..." --cn "..." --source "..."   # 固定文案，保证两次可比

# 改完代码后再跑一次 --tag after，然后：
node app/inspect.js --diff before after
```

常用参数：`--tag <名>`（输出后缀，默认 latest）、`--raw`（只截海报）、`--full`（整页截图，
海报比视口高时必须加）、`--desktop`（桌面视口）、`--long`（长版）、`--bg`（背景模式）、
`--word/--en/--cn/--source`（固定文案）、`--base`（服务地址）、`--no-shot`。

完整使用说明（就位检查、示例图、报修改句式、排查表）见
[`../docs/标注通道-使用手册.md`](../docs/标注通道-使用手册.md)。

### measure.js（2026-09-22 加）：按「现象」量数字，**默认不出图**

与 `inspect.js` 互补：inspect 给「编号 → 坐标」的清单（给人看图认编号），measure 给
「当前实现是否符合预期」的体检报告（给双方读数字，可 `--json` 给 AI 读、可 `--checks` 给 PASS/FAIL）。

```bash
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  node app/measure.js                       # 默认手机视口 390×844@2x 一次性体检
  node app/measure.js --voice --checks      # 连波形一起量 + 逐条 PASS/FAIL（有 FAIL 退出码 1）
  node app/measure.js --zoom badge-date=3   # 先把 2 区放到 3 倍再量（可重复，走 __ds.setZoom）
  node app/measure.js --standalone          # 独立全屏形态桩（量 --stage-pt 补正）
  node app/measure.js --viewport desktop    # 也可写 402x874 这类具体尺寸；--long / --fit / --raw 同 inspect
  node app/measure.js --json                # 机器可读（配置 + 全部读数 + checks）
  node app/measure.js --voice --crop 3      # 唯一会写文件的开关：出 3 区的局部放大图（--dpr 可调倍数）
```

报告分五节：① 画布与显示（含**海报圆角 = 32 设计值 × 显示比例**）② 三段几何与四个文字区
（`box` / `font` / `fx` / `base`）③ 波形（面板 rect、**相对 3 区文字框的左右留白**、与中文句 /
日期胶囊的间距、竖条数与覆盖率、有没有底板）④ 圆角自证（画布四角 alpha / 圆角内 / 边中点）
⑤ 语音自证（`hasAudio`、`state.voice`、`voiceDiag` 全字段）。读数全部走 `__ds.inspect()` 与
`__ds` 既有出口（只有波形面板与画布像素必须碰 DOM），与 `ui-check.js` 的断言同一套算法。

产物在 `app/shots/`（已 gitignore）：

- `inspect-<tag>.json` —— 版面清单：`items[]`（`i` 编号 / `id` / `label` 中文名 /
  `box` [x,y,w,h] 画布坐标 1080 基准 / `font` 字号 / `text` / `kind`）、
  `gaps[]`（间距量尺）、`opts` / `ratios` / `meta`
- `annot-<tag>.png` —— 带编号框的标注图（红实线 = 内容元素，黄虚线 = 安全边距）

`--diff` 输出两份清单的逐项变化（Δbox / 字号 / 新增移除 / 间距变化），改完自证改动范围。

### 命名表（共同词汇，说话以此为准）

> **标准版只出现 6 项**：`bg / badge-date / en / cn / source / card`。
> `title / rule / panel* / def-* / chip-* / ex-* / badge-src / safe-*` 只在长版（`?long=1`）出现。

| id | 中文名 | 备注 |
| --- | --- | --- |
| `title` | 大标题关键词 | 仅长版；118px 起，放不下自动缩 |
| `badge-date` | 日期胶囊 | 中部区域顶部靠右（右线 48）；**单击 = 切今日/昨日**，双击 = 删掉它 |
| `rule` | 标题分隔线 | 仅长版 |
| `en` / `cn` | 英文句 / 中文句 | 左线 48；**单击 = 朗读**，双击 = 删掉它；上下拖动 = 缩放字号 |
| `source` | 出处 | `—— ` 前缀一起算在框里 |
| `panel` | 单词卡整体 | 毛玻璃卡片 |
| `panel-bar` | 左侧渐变竖条 | |
| `panel-word` | 卡内关键词 | 与 `title` 是同一个词的两处呈现 |
| `panel-ph` | 音标 | 等宽字体，挤了会逐档缩小 |
| `def-0…n` | 释义第 N+1 条 | 框含行首词性 |
| `chip-0…n` | 词性胶囊 | n. / v. / adj. |
| `ex-0…n` | 例句块 | 仅长版海报出现 |
| `badge-src` | 右下来源圆标 | `补` / `选`，仅兜底内容出现 |
| `card` | 个人信息卡 | 标准版固定 x=48、984×496（三边等距 48） |
| `bg` | 背景图区 | 标准版 = 顶部固定 648px（默认铺满裁切）；长版 = 整张画布或图片自然高度 |
| `safe-l` / `safe-r` | 左 / 右安全边距 | 仅长版，各 84px |

间距量尺：

- **标准版**：`img-h`（顶部图片区 648）、`band-top`（图片区→中部活动区顶 104）、
  `band-h`（活动区高度 576）、`gap-img-text` / `gap-text-card`（文字块上下余量，相等即居中）、
  `margin-x`（正文与信息卡距左右 48）、`bottom-pad`（信息卡→海报底 48）、`card-h`
- **长版**：`margin-x`（84）、`top-pad`、`gap-title-en`、`gap-text-panel`、`gap-panel-card`、
  `bottom-pad`、`card-h`

说「这两块太挤」时，直接引用其中一个 id 即可被翻译成数值改动。文字字号另有
`text.fx`（2/3/4/5 各区自己的交互倍率，1 = 设计基准）与 `text.base`（保底倍率，
只有整块装不下活动区时才 < 1）两个字段 —— 实际字号 = 设计基准 × `base` × `fx`，
可以用 `--diff` 自证「字体改了多少」。

> 标注只在 `?debug=1` 下生成（`window.__ds.inspect()`），生产渲染路径零开销；
> 标注坐标由 `state.layout` 派生并与点击命中表自校验，不一致会在控制台告警。
